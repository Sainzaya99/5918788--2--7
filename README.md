# 과제 07: 인접 행렬과 인접 리스트의 성능 비교

## 1. 프로그램 설명

- 파일: `main.c` 
- 정점 100개짜리 그래프를 두 개 랜덤으로 만듭니다.
  - 희소 그래프: 간선 100개
  - 밀집 그래프: 간선 4,000개
- 같은 간선을 인접 행렬과 인접 리스트에 똑같이 넣기 때문에 두 방식은 같은 그래프입니다.
- 실행할 때마다 그래프가 달라지므로, 비교 횟수는 대략적인 범위로 적었습니다.
- 비교 횟수는 "확인한 칸(노드)의 수"입니다. 행렬은 `matrix[u][v]` 한 칸이면 1회, 리스트는 노드를 차례로 확인한 만큼입니다.

## 2. 결과

| 항목 | 희소 / 행렬 | 희소 / 리스트 | 밀집 / 행렬 | 밀집 / 리스트 |
|---|---|---|---|---|
| 메모리 | 40,000 B | 4,000 B | 40,000 B | 128,800 B |
| 간선 삽입 | 1 | 0~5 | 1 | 70~90 |
| 간선 삭제 | 1 | 1~10 | 1 | 10~130 |
| 연결 여부 확인 | 1 | 0~5 | 1 | 1~80 |
| 인접 정점 출력 | 100 | 0~6 | 100 | 70~90 |

- 행렬 메모리 = 100 × 100 × 4 B. 리스트 메모리 = 정점 배열 800 B + 노드 수 × 16 B (간선 1개당 노드 2개)

## 3. 분석

**희소 그래프** (한 정점에 이웃이 평균 2개)
- 리스트는 줄이 짧아서 메모리가 행렬의 약 1/10입니다.
- 인접 정점 출력은 행렬은 항상 100칸을 보지만, 리스트는 이웃 수만큼만 봅니다. 리스트가 훨씬 빠릅니다.
- 나머지 연산은 리스트도 몇 회로 끝나서 큰 차이가 없습니다.

**밀집 그래프** (한 정점에 이웃이 평균 80개)
- 행렬은 칸이 거의 다 차 있어서 낭비가 적고, 리스트는 노드마다 포인터가 붙어 메모리가 약 3.2배 더 듭니다.
- 행렬은 삽입·삭제·연결 확인이 항상 1회이지만, 리스트는 줄이 길어서 수십 회 이상 걸립니다.
- 인접 정점 출력도 행렬 100회, 리스트 약 80회로 거의 같습니다.

**언제 무엇을 쓸까?**
- 간선이 적은 그래프 → **인접 리스트** (메모리 절약, 이웃 탐색이 빠름)
- 간선이 많은 그래프, 연결 확인을 자주 함 → **인접 행렬** (1회로 확인)

**결론**: 인접 행렬은 간선 수와 상관없이 일정하고, 인접 리스트는 간선이 많아질수록 느리고 커집니다. 그래서 그래프의 밀도에 맞게 골라야 합니다.
